# Vaultly UI 重设计方案（提案 v1）

> 状态：**已实施（P0-P2 完成，P3 桌面适配延后）** ｜ 日期：2026-10-24 ｜ 范围：presentation 层，不动业务逻辑/加密/存储层
>
> 实施记录：靛蓝配色方案 A、4 tab 导航、JetBrainsMono 字体改为本地资产打包（未用 google_fonts，离线更可靠）、桌面适配 P3 延后。

## 0. TL;DR

- **框架层**：继续用 Flutter + Material 3，不换 UI 框架；仅引入 2 个小库（等宽字体、列表滑动操作）。
- **架构层**：新增底部导航（保险库/收藏/工具/设置）+ 统一设置中心，解决当前"功能入口全堆在 AppBar 图标上"的问题。
- **视觉层**：设计令牌升级（品牌色精炼、条目类型色纳入主题体系、等宽字体用于密码/验证码），列表项与详情页做减法（去渐变条、去重装饰）。
- **实施**：4 个阶段（P0 主题与导航骨架 → P1 核心页面 → P2 工具与设置 → P3 桌面适配），每阶段可独立验收、可随时停在任意阶段。

## 1. 现状诊断

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| 1 | **导航架构缺失**：云同步、生物识别、锁定三个入口全部挤在主页 AppBar 的图标按钮上 | `vault_page.dart:139-158` | 功能可发现性差，后续每加一个设置项都要往 AppBar 塞图标，不可扩展 |
| 2 | **没有设置中心**：WebDAV、生物识别是两个孤立路由页面，无主题切换、无自动锁定配置入口 | `app_router.dart:107-123` | 设置类功能没有归属，用户找不到 |
| 3 | **类型色与主题脱节**：条目类型色直接用 `Colors.blue/green/orange/purple/grey` Material 默认色，明暗模式无适配 | `entry_type_helper.dart:15-23` | 与精心调过的 Indigo 主题混在一起显得廉价；深色模式下橙色/amber 对比度失控 |
| 4 | **视觉装饰过度、信息密度低**：列表卡片同时有"左侧 5px 渐变条 + 图标渐变徽章 + 描边 + 双层阴影"；详情页 180px 渐变 Hero 头图 | `entry_card_widget.dart:100-139`、`entry_detail_page.dart:162-222` | 噪音大，密码管理器需要的是"安静、可信、扫一眼定位"，而非电商式氛围 |
| 5 | **关键信息没用等宽字体**：密码、TOTP 验证码、卡号与正文同字体 | 全局 | `0/O`、`1/l/I` 无法区分，是密码类产品的硬伤 |
| 6 | **动效各自为政**：入场用 `TweenAnimationBuilder`、按压用 `AnimationController`、FAB 用 `AnimatedScale`，曲线不统一（部分 `easeOutQuart` 部分 `easeInOut`） | 多处 | 细节质感不齐 |
| 7 | **移动单列布局，无桌面适配**：Windows/macOS 在 README 中"开发中"，当前布局宽屏下拉伸严重 | 全局 | 桌面端上线前必须处理（可延后到 P3） |

另：`AppTokens` 里定义了 `glassBlur`/`glassShadow`/`surfaceGradient` 但全项目几乎未使用——属于"设计系统说了没做"，本方案一并清理或落实。

## 2. 技术选型（框架层）

| 方案 | 内容 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 纯 Material 3 自建 | 零新依赖，升级现有 tokens/theme | 无依赖风险 | 等宽字体、滑动操作要手写 | — |
| B. **M3 + 2 个精品库（推荐）** | `google_fonts`（仅 JetBrains Mono）+ `flutter_slidable`（列表滑动操作） | 改动小、收益大；字体支持运行时下载与打包两种模式 | 多 2 个轻依赖 | ✅ **推荐** |
| C. 换风格化框架（forui/shadcn-flutter、fluent_ui 等） | 整体换皮 | 视觉独特 | 现有 6600 行 presentation 代码全部重写；forui 迭代快、API 不稳；移动端 M3 才符合平台习惯 | ❌ 不建议 |

**为什么不换框架**：项目已深度使用 M3 组件（SliverAppBar、FilterChip、NavigationBar 等），换库等于重写全部 UI 且丢失无障碍/本地化红利。方案 B 在保留 M3 的前提下把"质感"补齐。

可选加固（不强求）：`flutter_animate` 统一动效语法。我认为现有 Animation 体系够用，先不引入，保持依赖最小。

## 3. 设计语言

### 3.1 设计原则

1. **安静的工具感**——密码管理器一天打开几十次，UI 必须低噪音、高扫读效率；装饰服务于信息层级。
2. **类型即颜色**——四种条目类型有稳定的专属色相，用户靠颜色即可盲定位列表项。
3. **敏感数据等宽**——一切机密值（密码/验证码/卡号/密钥）一律等宽字体。
4. **明暗双主题完整**——每个颜色都有 light/dark 两套值，不用 withAlpha 糊弄对比度。

### 3.2 色彩（待拍板，二选一）

**方向 A（推荐）：「靛蓝保险库」**——延续现有品牌资产，精炼执行

| 令牌 | Light | Dark | 用途 |
|------|-------|------|------|
| primary | `#4F46E5` Indigo 600 | `#818CF8` Indigo 400 | 品牌主色、CTA |
| primaryContainer | `#E0E7FF` | `#312E81` | 选中态、chip 激活 |
| 类型-login | `#0284C7` Sky 600 | `#38BDF8` Sky 400 | 登录凭证 |
| 类型-bankCard | `#059669` Emerald 600 | `#34D399` Emerald 400 | 银行卡 |
| 类型-secureNote | `#D97706` Amber 600 | `#FBBF24` Amber 400 | 安全笔记 |
| 类型-identity | `#7C3AED` Violet 600 | `#A78BFA` Violet 400 | 身份信息 |
| 类型-custom | `#64748B` Slate 500 | `#94A3B8` Slate 400 | 自定义 |
| favorite | `#F59E0B` | `#FBBF24` | 收藏星标 |

理由：Tailwind 600/400 双档在两种亮度下对比度都达标；比 Material 默认色更沉稳；主色延续 Indigo 不推翻品牌认知。

**方向 B：「墨金金库」**——深色优先，near-black `#0B0F1A` 表面 + 金色 `#F5B301` 强调，更有个性，但浅色模式难做好、且与现品牌断裂大。除非你想彻底换形象，否则选 A。

> 实施要点：类型色从 `EntryTypeHelper` 的 `switch` 迁到 `AppTheme` 内，由 `ColorScheme` 扩展（`extension VaultlyColors on ColorScheme`）提供，dark/light 自动切换。

### 3.3 字体排版

| 场景 | 字体 | 说明 |
|------|------|------|
| 界面正文/标题 | 系统默认（不引入） | 中文字体网络字体体积过大，系统栈在各平台表现最好 |
| **密码 / TOTP / 卡号 / 密钥** | **JetBrains Mono**（google_fonts） | 等宽、`0O 1lI` 可区分，工具感强 |
| 数字徽标（倒计时等） | JetBrains Mono | 与验证码风格统一 |

排版尺度沿用 M3 TypeScale，补一个 `textTheme` 定制：标题 `w700 / letterSpacing -0.5`（现状已散落各处手写 copyWith，统一进主题）。

### 3.4 形状 / 间距 / 高度

保留现有 `AppTokens` 间距体系（4/8/12/16/24/32/48），调整：

- 圆角收敛为两档主用：`radiusM=12`（输入框/按钮/chip）、`radiusL=16`（卡片/弹窗底），`radiusXL=24` 仅 FAB 与大弹层；去掉 `radiusCircle=999` 这类魔法值改为 stadium 语义。
- 卡片高度策略：**描边为主、阴影为辅**（浅色 `outlineVariant@60` 描边；仅按压/悬浮给一层轻阴影），废弃现在的双层阴影。
- 删除未使用的 glass/glassShadow 令牌，或仅在解锁页背景落实一次。

### 3.5 动效

统一 motion 规范（写死在 tokens，禁止页面随手指定曲线）：

| 名称 | 时长/曲线 | 用途 |
|------|-----------|------|
| tap | 100ms / easeOut | 按压反馈 |
| micro | 180ms / easeOut | chip 切换、图标切换 |
| page | 240ms / easeOut | 页面转场（go_router 统一 shared-axis：push 上滑入场、pop 下滑出场；替换现在的纯 fade） |
| stagger | 30ms/项，上限 8 项 | 列表入场 |

## 4. 信息架构与导航重构

### 4.1 新导航结构（移动端）

```
底部 NavigationBar（M3）
├── 保险库 (VaultPage)      ← 默认 tab
├── 收藏 (FavoritesPage)    ← 新页面（复用列表组件，EmptyState.factories 已预留）
├── 工具 (ToolsPage)        ← 新页面：密码生成器（从 dialog 升级为页面）+ 未来 TOTP 工具
└── 设置 (SettingsPage)     ← 新页面：设置中心
```

- 主页 AppBar 只保留：**标题 + 搜索 + 锁定**；云同步/生物识别移入设置。
- 路由结构改为 `StatefulShellRoute`（go_router 官方底导航方案，各 tab 状态独立保持）。
- 收藏 tab 与工具 tab 让 `EmptyState.favorites/sync` 这些已预留工厂真正投入使用。

### 4.2 设置中心（新页面）收纳清单

| 分区 | 条目 | 去向 |
|------|------|------|
| 同步 | WebDAV 配置与同步 | 现有 `/webdav`、`/webdav/config` 两页整体内嵌为子页 |
| 安全 | 生物识别解锁、自动锁定时长、剪贴板自动清除 | 生物识别用现有页；后两者新增（auto_lock_service 已有底子） |
| 外观 | 主题模式（跟随系统/浅色/深色） | 新增，`themeMode` 进 Riverpod + 持久化 |
| 关于 | 版本、开源许可、导出备份 | 新增 |

### 4.3 桌面端（P3，先立规划不实施）

宽屏（≥900px）时：底部栏换 `NavigationRail`，保险库采用 master-detail 双栏（列表左、详情右），避免单列拉伸。

## 5. 关键页面重设计

### 5.1 解锁页 `/unlock`

现状：渐变背景 + 卡片表单，气质尚可。
调整：
- 品牌区（logo + "Vaultly"）居中上移，密码输入框全宽，生物识别大圆钮置于密码框下方。
- 失败抖动保留（体验好），错误提示从 SnackBar 改为输入框下方内联红字（SnackBar 会被系统剪贴板提示淹没）。
- 背景：方向 A 则 surface 纯色 + 顶部 primary@4% 渐变；落实一次现有的 glass 装饰或彻底删除该令牌。

### 5.2 保险库主页 `/vault`（核心）

改动清单：
1. 搜索框改用 M3 `SearchBar` 视觉（保留现有行为：即时过滤标题+标签）。
2. 筛选 chips 保留横滑，增加每类数量徽标（如 `登录 12`）；选中态用 `primaryContainer`。
3. **列表分组**：收藏置顶组分隔线 + 其余按类型分组（组头：类型色小图标+名称+数量），搜索时扁平化。
4. **列表项减法重设计**（EntryCardWidget v2）：
   - 去掉左侧 5px 渐变条、双层阴影；
   - 保留 44px 圆角图标徽章（类型色 12% tint 底 + 类型色图标）；
   - 副信息改为**类型相关的实质信息**：登录→用户名；银行卡→`**** 1234`；笔记→首行摘要；身份→姓名；不再是"标签·时间"；
   - 时间戳移到按更新分组时显示或长按菜单，列表里删除；
   - 收藏星标保留右侧。
5. **滑动操作（P2）**：右滑复制密码（登录类）/左滑收藏，用 flutter_slidable。
6. FAB 保留 extended "添加"，滚动隐藏逻辑保留。
7. 空状态升级：图标 + 标题 + 副标题 + 主按钮保留，视觉换成类型色描边圆底（现有 EmptyState 结构不动，只调皮肤）。

### 5.3 条目详情页 `/entry/:id`（核心）

现状 851 行，视觉重、交互弱。重设计：
1. **去 180px 渐变 Hero**，改紧凑头部：64px 类型图标徽章 + 标题 + 类型 chip + 创建时间， AppBar actions 保留（收藏/编辑/删除）。
2. **字段行组件 `FieldRow`**（新共享组件）：`label + 等宽值（遮罩态 `••••••••`）+ 眼睛切换 + 复制按钮`；整行点按=复制主字段（用户名/密码），复制成功该行右侧闪现 ✓ 动画 + 触觉反馈。
3. **TOTP 展示强化**：6 位码等宽大号分两组（`123 456`），右侧环形倒计时（30s），到期翻牌动画；一键复制。
4. **银行卡可视化卡面**：渐变卡面（类型色 15%→5% tint）+ 银行名 + `**** 1234` + 有效期，下方 FieldRow 提供复制。
5. 危险操作（删除）保留二次确认弹窗（现有 ConfirmDialog 已支持 danger 样式）。
6. 元信息（创建/更新时间、UUID）收进底部"关于此条目"折叠区。

### 5.4 添加/编辑页 `/add`

现状 934 行四类表单混在一起。调整：
1. 类型选择器保留横排网格（TypePicker 视觉微调：选中态类型色描边+tint，去阴影）。
2. 编辑模式下锁定类型切换（防止数据错位，现状似乎可切，需确认）。
3. 分区卡片 SectionCard 保留，标题从 primary 色改 onSurface（降低视觉级别），图标用对应类型色。
4. 密码字段区：生成按钮内嵌输入框 suffix；强度条保留（配色沿用 dialog 里的明暗适配逻辑，抽成共享组件）。
5. 表单页转场从 push 改 **bottom sheet 风格上滑全屏**（移动端更符合"创建流"心智）。
6. （P2）长表单加保存快捷栏。

### 5.5 工具页（新）：密码生成器

- 从 `PasswordGeneratorDialog`（213 行）升级为页面：参数（长度滑条、四类字符开关、易读模式）+ 大号等宽结果 + 强度条 + 一键复制/重新生成。
- Dialog 保留给"添加条目内快捷生成"场景，两处复用同一个生成器核心组件。

### 5.6 WebDAV 同步/配置页

- 视觉对齐新令牌即可（描边卡片、主按钮）。
- 同步状态区改三态设计：未配置（EmptyState.sync 引导）/已配置(最后同步时间+上传/下载双按钮)/同步中(进度)。
- 上传/下载是危险操作（覆盖），确认弹窗保留并统一用 ConfirmDialog（现在 download 用的是裸 AlertDialog，`webdav_sync_page.dart:91`，与 confirm_dialog.dart 重复，合并）。

### 5.7 全局反馈

- 复制类轻反馈：SnackBar 改为**轻量 toast**（自建 30 行组件：底部浮动、图标+文字、1.5s 自动消失、不打断输入焦点）。
- 错误类反馈：内联或 ConfirmDialog 样式，保留 SnackBar 仅用于异步任务结果。

- 页面里手写的 `copyWith(fontWeight…)` 尽量收敛进 `app_theme.dart` 的 textTheme。

## 8. 待你拍板的决策点

1. **配色方向**：A 靛蓝保险库（推荐，延续品牌）/ B 墨金金库（个性大改）。
2. **底部导航 4 tab** 是否接受（含新增收藏页、工具页）？还是保持单页+设置入口的极简结构（2 tab 也行：保险库/设置）？
3. 是否引入 `google_fonts`（JetBrains Mono 需打包字体文件，apk 体积 +~100KB；也可用手写 bundle 字体资产方式）。
4. P3 桌面适配现在做还是等桌面端发布前再做。

## 9. 风险与不变式

- **不动**：加密、存储、同步、TOTP 业务逻辑；路由路径全部保留（新增 `/favorites` `/tools` `/settings`，旧路径不删，深链兼容）。
- 视觉重做不改变任何交互数据流（Riverpod providers 原样复用）。
- `widget_test.dart` 若断言了旧样式文案/结构，P0 时同步更新。
